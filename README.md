# Лабораторная работа №6 - Введение в Node.js и базовый сервер на Express

## Вариант 2 - "Часы и часовые пояса" (API времени)

### Описание проекта

Веб-приложение для получения текущего времени с учётом часового пояса пользователя. Серверная часть реализована на Python с использованием фреймворка Flask. Часовой пояс определяется на стороне браузера и передаётся серверу через API.

Проект также реализует функциональность **Progressive Web App (PWA)**, позволяющую устанавливать приложение на устройство и пользоваться его статическими ресурсами без подключения к интернету.

### Функциональность сервера

Сервер предоставляет следующие маршруты:

| Маршрут | Описание |
|---|---|
| `/` | Главная страница. |
| `/about` | Страница "о себе". |
| `/api/time` | API для получения текущего времени. |

### API времени

Единственный динамический ресурс сервера реализован через `GET /api/time`.

**Параметры запроса:**

| Параметр | Описание |
|---|---|
| `format` | Формат отображения времени: `24` или `12`. По умолчанию - `24`. |
| `timezone` | Часовой пояс в формате IANA, например `Asia/Tomsk` |

В случае отсутствия параметра часового пояса, он определяется в браузере с помощью `Intl.DateTimeFormat().resolvedOptions().timeZone` и автоматически передаётся серверу при выполнении API-запроса путём его перехвата на стороне фронтенда.

**Пример запроса:**

```http
GET /api/time?format=12?timezone=Europe/Berlin
```

**Пример успешного ответа (`200 OK`):**

```json
{   "time": "07:02:15 PM",
    "timezone": "Europe/Berlin",
    "format": "12h"
}
```

При использовании 24-часового формата время возвращается в виде `HH:mm:ss`, при использовании 12-часового - в виде `hh:mm:ss AM/PM`.

В случае ошибки получения или обработки данных сервер возвращает статус `500 Internal Server Error`:

```json
{ "error": "Internal server error" }
```

### Реализация PWA

Для реализации Progressive Web App используются Web App Manifest и Service Worker.

**Web App Manifest (`manifest.json`)**

Определяет параметры устанавливаемого приложения:

- название и краткое название;
- описание;
- стартовый URL;
- область действия приложения (`scope`);
- режим отображения (`display`);
- цвета интерфейса;
- иконки приложения.

Приложение поддерживает установку на устройство и запуск в отдельном окне браузера в режиме `standalone` (поддерживается не во всех браузерах: рекомендуется использовать _Chromium_).

**Service Worker (`sw.js`)**

Реализован Service Worker со следующими возможностями (частично отображают его жизненный цикл):

- **Регистрация** - подключение Service Worker к веб-приложению;
- **Предварительное кэширование** - загрузка HTML-страниц, CSS, JavaScript, изображений и Manifest в Cache Storage при установке;
- **Обновление кэша** - использование версионирования для управления кэшами разных версий приложения;
- **Очистка устаревших кэшей** - удаление кэшей предыдущих версий при активации нового Service Worker;
- **Перехват запросов** - обработка сетевых запросов через событие `fetch`;
- **Офлайн-доступ** - использование стратегии Cache First: сначала выполняется поиск ресурса в Cache Storage, а при его (ресурса) отсутствии используется сетевой запрос.

Для кэшей используется общий префикс `app-cache-v`, что позволяет удобно находить устаревшие кэши, подлежащие удалению, и не трогать остальные (в данном веб-приложении используется всего один кэш, но это полезная практика при реализации более масштабных проектов).

Динамические ответы API предварительно не кэшируются.
Таким образом, статические ресурсы приложения остаются доступными без подключения к серверу, а для получения актуального времени требуется его (сервера) доступность.
